# Task 18 rendering prerequisites and primary evidence

Pillow remains pinned to12.3.0. The initial macOS wheel reported RAQM/FriBiDi/HarfBuzz false; FreeType true. Root's immutable reviewed Linux API image also reported all three shaping flags false. Ordinary wheel installation is therefore insufficient for the eight-script acceptance.

[Official Pillow source-build documentation](https://pillow.readthedocs.io/en/stable/installation/building-from-source.html) identifies libraqm, FreeType, HarfBuzz and FriBiDi as complex-layout dependencies. [Pillow12.3.0's official pyproject](https://github.com/python-pillow/Pillow/blob/12.3.0/pyproject.toml) requires setuptools>=77 and pybind11 for building. `api/requirements-build.txt` pins the current compatible official-registry releases setuptools84.0.0 and pybind11 3.1.0. This is build tooling, not a replacement package manager.

Root authorized the specific native-build window. `brew install libraqm` installed0.11.0; existing FreeType2.14.3, FriBiDi1.0.17, HarfBuzz14.5.1 and GLib2.90.0 stayed unchanged. Rebuilding with `pip install --force-reinstall --no-deps --no-binary=Pillow -C raqm=enable Pillow==12.3.0` produced a source-built wheel with SHA256 `0ad5795192a1eb3451fdf31e437c8cb1bf55bc6628d5c344a05a58da1a17df2c`. Actual capabilities became RAQM true(0.11.0), FriBiDi true, HarfBuzz true, FreeType true(2.14.3); pip check passed. The final documented installation additionally disables cache/build isolation and installs pinned build requirements, so a fresh install or explicit repair does not silently substitute a wheel without shaping.

The Linux recipe builds wheels on the existing digest-pinned Python3.12 Bookworm base using `libraqm-dev`, FreeType/JPEG/zlib headers and the pinned Python build requirements, forces the same Pillow source build with RAQM enabled, then installs those wheels into a separate non-root runtime with matching native libraries. The image build explicitly fails if required shaping features are absent. Debian packages come from the distribution repository; exact byte-identical native builds are not claimed. Root owns actual Docker parity/build verification; no Docker build ran in this execution lane.

Fonts are unmodified Noto Sans, Sans SC, Sans Tamil, Sans Bengali, Sans Devanagari and Sans Myanmar variable TTF assets from [the official Google Fonts repository](https://github.com/google/fonts/tree/66928797f271fed5ee428544e7229685e2d90127/ofl). `api/fonts/manifest.json` records that exact commit, asset URLs and SHA256 hashes; each family's SIL Open Font License1.1 is bundled. No report/card runtime downloads fonts. [FontTools ttLib](https://fonttools.readthedocs.io/en/latest/ttLib/index.html) supplies actual cmap coverage for mixed-script names; pinned fonttools4.66.1 supports the runtime Python. Pinned regex2026.9.29 supplies Unicode grapheme clusters for wrapping without splitting Indic/Myanmar clusters. These utilities do not change the Pillow rendering stack.

The renderer always requires RAQM, checks glyph coverage and rejects unsupported output instead of emitting missing-glyph boxes. Measured text/legend heights and grapheme-safe wrapping prevent silent clipping; a context too large for the bounded layout fails explicitly. Source coordinates stay unchanged even when coincident schematic pins use small leader offsets. Native-language review and real-world destination opening/route safety remain unverified.
