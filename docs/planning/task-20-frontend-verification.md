# Task20 frontend candidate

The frontend consumes the frozen `ReportWaste` and `WasteResponse` contracts. Files changed are `web/lib/contracts.ts`, `web/lib/proxy.ts`, `web/components/report-view.tsx`, `web/components/dashboard-view.tsx`, `web/app/globals.css`, new `web/lib/waste-summary.ts`, new `web/components/waste-summary.tsx`, new `web/tests/waste.test.ts` and two sanitized waste fixtures. No backend, catalogs, dependencies, lockfiles or running services changed.

Reports without the additive waste field normalize to not assessed. Available waste items join every canonical baseline report item by identity and condition; duplicates, missing/extra IDs, invented quantities for missing stock, contradictory donation facts and changed fixed food warnings fail validation. Existing loss figures, selected-video binding and all evidence receipts remain unchanged. Waste uses fixed handling labels, canonical uncertainty language, explicit material/contact/contamination attribution, confidence and unknown quantities. It does not display free-form model disposal advice or claim safety. Current owner-confirmed street metadata remains distinct from immutable assessment facts.

Donation actions accept only canonical `https://t.me/<5..32 username>?start=donate_<32 lowercase hex>` links without credentials, port, fragment or extra query. They are shown only for eligible assessed items and open the existing owner-confirmed Telegram flow. A report capability provides no write access and is never attached to the link. Owner-reported availability does not establish safety or collection. Action controls are hidden in print; the existing capability-stripping print lifecycle and explicit printable SHA256/byte receipts remain intact.

The public waste proxy permits only the exact GET path and strips bearer credentials and cookies through the existing fixed-origin boundary. The dashboard presents street summaries beside the existing map, with no invented geometry. It shows shop/item assessment coverage, unknown volume/weight counts, explicit m³/kg units, configured load capacity and estimated load-equivalents. Empty assessment scope is not zero waste. Unavailable data does not become a zero; a genuinely quantified zero remains distinct. Failed refresh clears that panel's data and states unavailable rather than presenting an unlabelled stale result.
