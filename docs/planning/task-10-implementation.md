# Task 10 implementation contract (local candidate)

Baseline: `1a4d7b1345b61dda187b1302138333bcdf18e48f`. This describes an in-progress implementation, not hosted acceptance. No Scheduler job, IAM binding, deployment or shared scenario reset has been performed.

`ActiveRiskStore.get(shop_id)` returns a typed `RiskState`: canonical shop `episode_id`, `active_danger`, `official_danger`, and `legacy_unknown`. `apply_event_decision` returns a typed rejection reason or the accepted canonical episode. `apply_event` retains the small `episode_id | None` adapter. Source episode identity remains separate from this shop scope; all concurrent sources in an open shop episode share the metric scope.

Official recovery removes only its matching source episode after a fresh explicit observation. Missing, stale, failed, unmapped and older observations do not clear Danger. Official watermarks keep an unresolved episode through a data gap; absence is not recovery. Source timestamps/timezones and coordinate attribution remain those accepted by the existing source parsers; no timezone or district centroid is guessed. Owner-declared photo recovery requires private owner membership and no official or unknown legacy Danger. Explicit operator demo reset closes the selected demo shop episode, records a closed-time boundary and rejects older prepared/report intents; it cannot resolve real official Danger.

`PollStore` writes each source watermark and stable event/recovery intent in one Firestore transaction. Dispatch carries private source key/episode/observation/expiry fields. The public simulation DTO still accepts only demo facts and forbids these internal controls. Source status and pending intents survive restarts.

A per-shop delivery lease serializes the actual Telegram send window. The final claim checks current risk, canonical episode and original observation freshness. Delayed Warning is superseded when Danger applies; an already in-flight ambiguous external request remains uncertain, because it cannot be retracted. The lease is longer than the transport timeout. Confirmation actions retain immutable displayed snapshots and the canonical shop episode; later aggregates must group vehicles once and stock MAX per shop/episode.

Scheduler authorization follows the [official HTTP authentication guide](https://docs.cloud.google.com/scheduler/docs/http-target-auth) and [google-auth verifier](https://github.com/googleapis/google-auth-library-python/blob/main/google/oauth2/id_token.py): configured audience, Google issuer/signature/expiry, verified exact caller email and exact subject. Certificate fetch is bounded to five seconds and synchronous verification runs off the event loop. Local operator authentication is a separate explicit setting requiring local development, demo mode, a loopback Firestore emulator and absence of Cloud Run runtime identity. Host headers confer no authority. `infra/scheduler.sh` requires explicit hosting authorization/project/caller/audience and prepares a five-minute job only when manually invoked later.
