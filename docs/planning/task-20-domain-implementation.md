# Task20 pure-domain preparation

This slice contains only `api/waste_models.py`, `api/waste.py` and `api/tests/test_waste.py`. It is not Task20 feature acceptance. No agent, existing report, storage, route, catalog, frontend, dependency or runtime has changed.

`WasteAssessment` is version1 and binds an inventory identity and exact selected assessment-media identity. Its bounded typed items carry the canonical loss condition, source disposition, finite optional volume/weight estimates, material, observed contact/contamination status and explicit uncertainty. `validate_waste` validates the existing LossAssessment against its frozen baseline/clip duration, then rejects changed, unknown, duplicate or omitted assessed item identities. It does not change loss amounts. Missing/unassessed items retain unknown contact/quantities, and unaffected items acquire no waste quantities. Legacy reports without waste remain outside this new contract rather than silently reassessed.

The fixed line is exactly: “Throw away food, drinks and medicine that touched floodwater.” Food/drink/medicine/cosmetics/absorbent contact forces `discard_contaminated`, including when a model's material conflicts with a canonical hazardous baseline category. Contradictory salvage/recycling/bulky classifications fail validation. The pure donation predicate requires separate explicit owner opt-in, an assessed salvage classification for sealed metal/plastic/glass, no observed contamination and no stated uncertainty. Contact alone does not disqualify these sealed materials; classification is not a safety certification. `not_observed` describes assessment evidence, not proven absence. Actual sender ownership, durable opt-in and availability flags are still an integration requirement; a report capability supplies none of that authority.

`WasteRecord` carries private attribution for a completed assessment. The aggregate reader must supply already-bound records and verified synthetic shop scope. `aggregate_waste` selects the latest completed record per shop/episode/inventory, retaining different episodes, and groups by owner-confirmed street or Unassigned. Public output contains no shop/episode/inventory/media identities, exact report coordinates or contacts. It reports baseline/assessed/affected item counts, omitted or missing-item coverage, independently unknown volume/weight counts and quantified estimate totals. No quantified contribution means unavailable, not zero. A genuinely quantified zero remains zero. Finite positive capacity defaults to10m³; calculated load-equivalents are estimates, not required trucks or a collection promise.
