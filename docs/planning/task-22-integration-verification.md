## Implemented boundaries

Explicit recovery records closure in that transaction. Source observation time and receipt-time fallback are labelled. `OutcomeService` uses random32hex owner/message-bound callbacks and the full canonical episode key on the server. Preparation and send states are durable; the prompt shares the existing shop delivery lease with alert sends and rechecks current owner, generation and Danger immediately before transport. Pretransport read/render errors remain retryable; ambiguous transport remains uncertain and is never blindly resent. Simulations and unreviewed translations are visible. The first owner response and pending analytics fact are atomic and immutable. `/outcome inside <ISO timestamp with timezone> [depth_cm]` requires a unique confirmed interval and an explicit owner-declared time; optional depth is a whole number0–1000. A later depth does not replace a first response.

`reference_basis` is episode_reference for a prompted answer and owner_declared for the explicit inside flow. Prompted time references the explicit closure endpoint, or the trusted first-event boundary of an open episode; it is not owner-observed/capture time. answered_at remains separate. Growth accepts only fresh owner-declared inside evidence with complete history proving no earlier accepted alert. Uncertain, pending, virtual or incomplete prior history never supplies that proof.

`POST /jobs/ask-outcomes` is manually invoked, protected by existing scheduler authorization and loopback-only development bypass. Limit1–20 is a work budget, not a response sample. The25-second response deadline retains and observes in-flight work; monotonic checks stop additional SDK calls between episodes/deliveries and calibration evidence reads. An already-started bounded call may overshoot. No automatic or cloud scheduler is installed.

Calibration builds the full relevant area/window response batch. More than100 eligible records defers that area explicitly, rather than calculating a ratio from the first20. Immutable consumed identities, exact persisted evidence and version transactions enforce disjoint batches. Private per-shop RadiusPlan freezes before distance filtering; public/base Event radius remains unchanged. Only nonofficial Warning dispatch uses learning. Official, Watch, Danger, fixed500m corroboration and public2km lookup bypass calibration storage. Optional learning outage freezes the configured base radius without claiming a learned version.

The existing BigQuery outcomes table receives eight nullable additive fields, with stable response ID and explicit time/provenance. Event ID is null when not known; no owner hash is published. OutcomeAnalytics requires deduped analytics to agree with scoped immutable first responses, reports missing sinks/overflow unavailable, and retains bounded FS calibration history with an explicit truncation flag. Public `/api/outcomes` is synthetic-only with no-store/no-referrer. `infra/seed_outcomes.py --apply` writes six labelled historical shop/episodes of one existing synthetic shop and demonstrates0.9→0.99, with no Telegram transport or accuracy claim.
