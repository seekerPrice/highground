# Task21 first domain and reader slice

This slice adds `api/public_check_models.py`, `api/public_check.py`, `api/public_check_store.py` and three focused test files. No shared route, webhook, configuration, catalog, agent, dependency or frontend was edited. It is not Task21 acceptance.

## Interfaces

`project_check(CheckLocation, tuple[SourceResult], tuple[PrivateCheckReport], tuple[SafePoint], now=..., official_max_age=..., report_source_available=...)` returns a strict `CheckResult`. The submitted location is transient. Private report input requires the actual32hex report identity, private shop identity/hash, confirmed coordinates/location attribution, server `received_at`, original Telegram `telegram_date`, `confirmed_at`, evidence status, attributed triage level or unknown, and simulation flag. None of the private IDs, hash, reasons, media or precise report coordinates appear in the public result. Distances are filtered at exact2,000m before rounding to100m. Time labels describe observation/report receipt provenance, not capture authenticity.

Official results reuse the existing parser contract and configured positive cutoff at most90minutes. Future/stale/expired warnings are rejected again at projection. A cached current source whose observations become stale is degraded rather than described as complete fresh coverage. District-only MET attribution remains separate, with no claim it lies within2km. Unverified reports without an established triage level retain unknown level. Report server and original Telegram receipt ages must both fit30minutes; confirmation cannot refresh their age. Simulations, rejected depictions and unconfirmed/future/contradictory confirmation times are excluded.

Private image SHA256 deduplicates known reports across different report IDs. The earliest known receipt wins, and conflicting coordinates for the same bytes are omitted with degraded availability. The actual reader deliberately scans the bounded real-report scope before age filtering, so an older known receipt is not hidden by a newer upload. More than1,000 real rows makes that source unavailable; it does not infer earliest provenance from a partial collection. This conservative limit is explicit; a larger retained dataset requires a separately reviewed trusted first-seen index rather than unbounded per-hash queries.

`PublicCheckReader.read(location)` uses read-only Firestore and the existing official fetch/parser. It reads at most1,001 real reports/registry rows with five-second SDK read timeout and no retry; overflow is unavailable. Eligible destination listings require checked sources, non-demo identity and non-closed status. The nearest listing per destination type uses actual distance and the configured registry radius. Public sourced coordinates and source provenance remain available; current opening/accessibility/safety are unverified. `destination_status` distinguishes unavailable listing data from a completed empty lookup.

Official HTTP reads use five-second request timeouts, one12-second overall async budget, a five-MB decoded-body limit and no retries. Already-decoded gzip headers are removed before reconstructing the bounded parser response. No source timezone or district geometry is guessed. `create_public_check_reader(settings)` propagates the configured freshness/radius and creates only an owned Firestore reader, never models, analytics, registration or risk writers. SDK read timeouts are attempt bounds: a worker thread already inside an SDK call is not forcibly cancelled by its awaiting coroutine. These limits are not a promise of exact whole-request wall time.

`FirestoreCheckIntentStore.open/active/claim/finish/retryable` atomically stores a hashed sender gate and stable hashed operation intent. Expiry is five minutes from the first opening, and first lookup reservation advances the sender rate gate by30seconds. Concurrent claims serialize; a60-second lease permits the same operation to resume. A different location operation cannot reuse a consumed intent. Same-operation replay returns the first sanitized result and its original checked timestamp; it does not persist or compare coordinates or a location fingerprint. Expired/superseded intent routing cannot claim another location flow. Records retain only hashes, timestamps, status/lease and sanitized JSON cache. Expiry denies use; this slice does not provision automatic deletion/TTL infrastructure.

`location_routing` gives an existing registration/media flow priority over a waiting public intent. The integration owner must supply actual waiting-flow state. `fixed_check_danger` uses the existing committed Danger renderer and eligible listed destination; it has no model/property branch. Final canonical sender/shop Danger guards and optional constrained Flash summary belong to later shared integration. No risk is mutated.

No external source, model or analytics call was made.
