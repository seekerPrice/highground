`record_response` reads the exact ledger, current shop owner, canonical risk and demo generation within one transaction. It rejects nonowners, obsolete generations, current Danger and a no-longer-current open episode. The first immutable response and pending analytics fact are written together. Observation time must additionally be established by the later trusted Telegram adapter; this method enforces aware clock/order and confirmed episode bounds, not independent physical water verification.

`calibrate` reads current version, canonical consumed-scope receipts, current demo generation and exact persisted episode/response evidence before deciding. It caps each transaction at100 evidence rows, uses separate constant-sized consumed receipts and writes the new version plus pending decision fact atomically. An exception or version conflict consumes nothing. Changed opaque response IDs cannot replay a canonical outcome scope. Adapter code must supply a complete bounded relevant batch, never a selectively filtered sample. Production analytics insertion, exact schema mapping and acknowledgement remain pending.
