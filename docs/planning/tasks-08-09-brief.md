## Task 9 — immutable media and neighbour reports

Implement shared ingestion with the official Telegram HTTP, Cloud Storage, Firestore and BigQuery clients. Enforce both declared and streamed byte limits; the standard getFile API limit is20MB. Give a fixed useful request for a shorter/compressed clip when exceeded. Preserve downloaded bytes exactly, hash SHA-256 before storage, use create-only object preconditions and stable media identity, and record receipt time, Telegram time, sender hash and explicitly attributed location. Never fetch arbitrary user URLs. Sanitise token-bearing download errors and logs.

Model and validate the multi-sink ingestion lifecycle. Retries resume the same media/object/ledger identity and must not overwrite originals or append a new logical upload. BigQuery dedupe is logical, not a false exactly-once streaming guarantee. On failure retain recoverable status without claiming an evidence record is complete. Derived files remain separate. `File integrity verified` requires comparing the stored bytes against the recorded hash; no claim of authenticity or correctness of scene/time/location.

Use local emulator endpoints only when validated loopback; otherwise real configured clients/credentials. The local GCS emulator has no production signed-URL enforcement. Vertex cannot read a local emulator gs:// object: for local actual multimodal probes, pass bounded downloaded bytes through the official SDK while retaining the original in local storage. Do not silently create a cloud bucket or claim cloud media access was tested.
